### Zusammenfassung für den Inhaber

Mit dieser Änderung gibt es den Befehl „cwk sync“. Er bringt den neuesten Stand der gemeinsamen Regeln und Werkzeuge per Pull Request in die anderen Repos, ohne dort etwas zu überschreiben, was du selbst auf dem Sync-Zweig geändert hast. Dazu kommen das private Repo „platform“, die beiden GitHub Apps und die Beschreibungen, wie man den Sync startet. Die Prüfungen sind grün, ein Blocker ist nicht dabei.

Es gibt zwei Schwachstellen:

- Scheitert ein Sync genau zwischen Hochladen und Anlegen des Pull Requests, meldet der nächste Lauf fälschlich „aktuell“, und es entsteht kein Pull Request.
- Wird eine Datei aus dem Werkzeugkasten gestrichen, verschwindet sie in den Projekten nicht.

Außerdem steht im Register, dass die Schreib-App schon in drei öffentlichen Repos installiert ist, belegt ist das aber noch nicht. Zum Ausprobieren: Nach dem Merge den Sync in „platform“ von Hand starten und prüfen, dass in „cwk-sample“ genau ein Pull Request mit altem und neuem Stand entsteht. Ein zweiter Start sollte denselben Pull Request nur aktualisieren oder „aktuell“ melden.
